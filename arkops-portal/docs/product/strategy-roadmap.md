# 产品战略路线图：AllMall ArkOps-Portal

> 版本：v1.0 | 更新日期：2026-08-10 | 关联任务：T-PROD-001 | 作者：Strategy-Agent

## 一、战略背景

### 1.1 治理基线摘要
- **当前阶段**：前端 Mock 验证阶段，无后端
- **核心资产**：15 Agent 体系已完整设计、13 个前端模块已实现、D1-D9 决策已落地
- **关键约束**：人在决策链上、多租户隔离、Mock 阶段不预设后端

### 1.2 市场上下文
| 维度 | 现状 | 判断 |
|------|------|------|
| 目标市场 | 全球电商 AI 运营工具，竞品多在 Amazon 生态 | **蓝海**：TikTok Shop/Shopee/Lazada/拼多多 多平台 Agent 几乎没有竞品覆盖 |
| 竞争格局 | CommerceIQ（品牌方）、实在智能（RPA）、领星（ERP内嵌）、多客AI（客服） | **差异化空间大**：唯一跨多平台 + 15 Agent 全链路 + 原生审批流 |
| 用户成熟度 | 中小卖家对 AI 运营有认知但无使用习惯 | **教育成本中等**，需要场景化引导降低门槛 |

### 2.2 北极星指标
- **指标**：连接店铺并至少运行 1 个 Agent 的周活跃店铺数
- **当前基线**：Mock 阶段无数据
- **本期目标**：确立指标口径和埋点方案
- **选此指标的理由**：连接店铺→开通 Agent→Agent 运行，是产品价值闭环的最短路径

## 三、竞品对标与差异化

### 3.1 直接竞品
| 竞品 | 核心能力 | 价格 | 优势 | 劣势 | 我们的差异化 |
|------|----------|------|------|------|-------------|
| CommerceIQ | 品牌方全链路 AI | 企业定制（$数万/年） | 效果验证最充分 | 仅 Amazon，无多平台 | 多平台覆盖（拼多多/TikTok/Shopee）+ 更低门槛 |
| 实在智能 | RPA 屏幕操控 | 企业定制 | 免 API 集成 | 稳定性依赖 UI 变化 | 原生 API 集成 + Agent 原生协同 |
| 领星 LinkFox | ERP 内嵌 AI Agent | ERP 订阅 | 生长在 ERP 骨架上 | 仅跨境，无国内平台 | 独立 SaaS + 覆盖国内外平台 |
| 多客AI | 客服场景 Multi-Agent | 按 Token 计费 | 客服最成熟 | 不覆盖运营全链路 | 15 Agent 全链路 vs 单客服场景 |

### 3.2 差异化策略
- **唯一的多平台 + 多 Agent + 审批流整合者**：竞品要么单平台、要么单场景、要么无审批。AllMall 是唯一把三者整合的产品
- **低门槛场景化激活**：D1 场景优先配置模型，新用户 5 分钟完成 Agent 开通，而非竞品的逐个配置
- **人机协作信任体系**：L1/L2/L3 自主度拨盘 + 信任累积，不是冷冰冰的"全自动"，而是"渐进式放权"

## 四、分期战略与节奏控制

### 4.1 分期定义与理由
| 分期 | 代号 | 时间窗口 | 核心命题 | 为什么是这个顺序 | 关键交付 |
|------|------|----------|----------|-----------------|----------|
| P0 | 信任修复 | 当前 | 修掉所有产品"欺骗感" | 审批假数据、一键全开无确认、退款无确认——这些在演示时直接破坏信任，"看起来 AI 失控了" | G01-G06 全部关闭 |
| P1 | 闭环打磨 | P0 后 | SPU+铺货完成 + 店铺智能完成 | 商品和店铺是最高频的操作入口，完成这两个模块的用户每天的体验是连贯的 | SPU+铺货 P1/P2、D7 第二轮 |
| P2 | 商业就绪 | P1 后 | 权限落地 + 运营支撑 | 真实用户需要角色隔离、操作日志、报告导出 | 权限拦截、审计增强、报告模块 |

## 五、商业化节奏

### 5.1 版本升级钩子设计
| 升级触发点 | 当前版本限制 | 目标版本能力 | 触发方式 | 预期转化率 |
|-----------|-------------|-------------|----------|-----------|
| 第 3 家店铺连接时 | 免费版≤2 店 | 标准版 10 店 | 弹窗 "你已有 3 家店铺，升级标准版管理全部店铺" | 预估 15% |
| 月操作次数达 400 次（预警） | 免费版 500 次 | 标准版 5000 次 | Dashboard 用量提醒 + 邮件 | 预估 10% |
| 点击"批量操作"时 | 免费版不支持批量 | 标准版批量能力 | 功能入口旁 "升级解锁批量操作" | 预估 8% |
| 需要自定义风控规则时 | 标准版固定规则 | 企业版自定义 | CSM 触达 | 预估 5% |

### 5.2 免费版留存策略
- **激活门槛**：连接 1 家店铺 + 开通 1 个 Agent + 看到 Agent 产生第一个成果（目标 15 分钟内）
- **留存钩子**：每周一自动生成"上周 AI 运营周报"推送，展示 Agent 帮你省了多少时间
- **流失预警**：7 天未登录 → 邮件 "你的店铺上周有 N 个 AI 可以帮你处理的事务"

## 六、风险与假设

### 6.1 关键假设清单
| 编号 | 假设内容 | 验证方式 | 验证时间 | 如果假设不成立 |
|------|----------|----------|----------|---------------|
| H-001 | 中小卖家愿意让 AI 自动操作店铺（非 RPA 录屏方式） | 内测用户访谈 | 首次内测 | 增加"推荐模式"：AI 只建议、不自动执行 |
| H-002 | 多平台覆盖（拼多多+TikTok+Shopee）是核心差异化 | 竞品持续监控 + 用户需求调研 | 每月 | 收缩平台，聚焦 1-2 个做深 |
| H-003 | 免费版→标准版转化率 ≥10% | 上线后 3 个月数据 | 上线后 | 调整免费版限制条件或标准版定价 |

### 6.2 战略风险
| 编号 | 风险描述 | 影响 | 概率 | 缓解策略 | 触发条件 |
|------|----------|:--:|:--:|----------|----------|
| S-001 | 平台 API 封禁/限流导致 Agent 无法操作 | 高 | 中 | 多平台分散风险，单一平台封禁不影响其他 | 任一平台 API 策略变更 |
| S-002 | CommerceIQ 或领星扩展到多平台 | 高 | 中 | 加速多平台差异化落地，建立迁移成本（审批流/历史数据） | 竞品宣布多平台支持 |

## 七、资源判断

### 7.1 做 / 不做 / 待定
| 要做（本期必做） | 不做（砍掉） | 待定（看数据再决定） |
|-----------------|-------------|---------------------|
| 审批证据真实化 — 破坏信任 | 多语言完善 — D4 已冻结 | 运营报告导出 — 等有真实数据 |
| Finance 角色补齐 — 产品设计 vs 代码不一致 | 移动端适配 — P3 | 日期对比分析 — 等 Dashboard 有真实数据 |
| 权限拦截 — 安全底线 | 模板市场 — 无用户基数 | Agent 搜索 — 15 个暂时不需要 |
| SPU+铺货 P1 — 最高频入口 | SSO/LDAP — 无企业客户 | 定价页 — 无付费流程 |
| UX 信任修复 4 项 High — 演示致命伤 | 自定义工作流 — P2 | |

### 7.2 如果资源砍半，保留什么？
只保留 P0 中 ICE 最高的 3 项：
1. **审批证据真实化**（ICE 810）— 不修复等于演示自杀
2. **退款/放行加确认弹窗**（ICE 720）— 不修复等于事故制造机
3. **角色权限拦截**（ICE 432）— 不修复等于没有多租户

这三项完成后，产品至少"不会在演示中出致命事故"。
