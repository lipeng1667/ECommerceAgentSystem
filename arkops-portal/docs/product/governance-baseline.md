# 项目治理基线：AllMall ArkOps-Portal

> 版本：v6.0 | 更新日期：2026-08-10 | 关联任务：T-PROD-001 | 来源：gov-agent

## 一、顶层定位

### 1.1 产品愿景
AllMall 是面向电商卖家的 AI 自动化运营 SaaS 平台。通过 15 个 AI Agent 覆盖电商运营全链路，替代人工执行重复性运营任务（广告优化、新品上架、CRM 复购、财务对账等），实现大规模店铺的高效自动化管理。

### 1.2 目标用户画像
| 用户群体 | 典型画像 | 核心痛点 | 使用频次 |
|---------|---------|---------|:--:|
| 中小卖家 | 经营 1-5 家平台店铺，团队 1-3 人 | 人力有限、多平台管理复杂、运营知识不足 | 日活 |
| 品牌电商团队 | 自有品牌，5-20 家店铺，专职运营 | 团队协作、运营标准化、数据驱动决策 | 日活 |
| 代运营机构 | 代管多个客户店铺，规模化管理 | 多客户管理、效率规模化、客户汇报 | 日活 |

### 1.3 核心价值主张
- **降本**：AI 替代人工执行定价、广告投放、客服回复、评价管理等重复运营
- **增效**：Agent 7×24 自动运行，响应速度远超人工
- **增收**：智能定价策略、广告优化、库存预警帮助卖家提升 GMV
- **安心**：审批 + 风控体系确保自动化不出格，人始终在决策链上

## 二、业务边界

### 2.1 范围内（In-Scope）
- 店铺连接与多平台授权管理（拼多多/淘宝/京东等）
- 15 个 AI Agent 的配置、运行、监控、审批闭环
- 商品主体（SPU）+ 铺货记录（Listing）两层模型
- 行动收件箱统一待办入口（审批 + 异常 + 重新登录）
- 经营总览 Dashboard + Agent 监控
- 订单自动化处理
- 成员管理 + 角色权限（6 角色：Owner/Admin/Operator/Approver/Finance/Viewer）
- 模型中心（Agent ↔ 模型分配）
- 财务台账（订阅/账单/用量/发票）
- 审计日志
- SaaS 订阅版（云端多租户）+ 本地部署版

### 2.2 范围外（Out-of-Scope）
- 后端 API 和数据库实现（当前 Mock 阶段）
- 移动端响应式适配（延至 P3）
- 多语言完整支持（已冻结，仅中文；i18n 基础设施保留）
- Agent 模板市场和自定义工作流编排（延至 P2）
- SSO/LDAP 对接（延至 P2）
- 真实支付/发票/订阅 API

## 三、商业化版本基线

### 3.1 版本分层策略
| 版本层级 | 目标客户 | 核心能力 | 限制条件 |
|----------|----------|----------|----------|
| 免费版 | 个人卖家（1-2 店） | 基础 Agent（3 个）、Dashboard 基础视图 | 最多 2 家店铺、月操作 500 次 |
| 标准版 | 中小团队（3-10 店） | 全部 Agent、高级配置、批量操作 | 店铺数≤10、月操作 5000 次 |
| 企业版 | 品牌/代运营（10+ 店） | 全部能力 + 自定义 + 专属支持 | 无限制 |

### 3.2 部署模式
| 模式 | 部署方式 | 计费方式 | 目标客户 |
|------|---------|---------|---------|
| SaaS 订阅版 | 云端多租户 | 订阅制 + 超额按量付费 | 中小型卖家、代理商 |
| 本地部署版 | 客户自有服务器/私有云 | 年付 License + 扩容 | 大型品牌、数据合规要求高的企业 |

## 五、治理约束

### 5.1 必须遵守的原则
1. **人在决策链上**：所有高风险操作必须经过审批，不可全自动执行
2. **多租户数据隔离**：任何设计不可出现跨租户数据泄露的可能
3. **店铺保活不可禁用**：作为基础设施 Agent，禁止关闭
4. **先 Mock 后真实**：前端 Mock 数据阶段以产品设计验证为主，不做后端假设
5. **代码与文档一致性**：product-design.md 为权威来源，代码实现必须对齐文档
