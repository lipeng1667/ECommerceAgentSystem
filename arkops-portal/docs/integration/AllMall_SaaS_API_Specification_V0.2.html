AllMall API Specification

SaaS 平台 API 接口文档 V0.2

本文档定义 AllMall SaaS 平台与 Portal、Agent / Runtime 的统一联调契约，覆盖店铺登录绑定、任务控制、审批、Runtime 回调，以及电商平台日常运营数据的只读采集、标准化回传和统计查询。

Backward Compatible Read-only Collection Daily Operations Data Multi-platform
运营数据范围：只从淘宝、拼多多、抖音电商、京东店铺后台读取运营数据。数据采集接口不会执行发货、退款、售后、评价回复、商品修改、调价、投放启停、活动报名或库存调整。

1. 文档范围

模块范围接口性质
店铺与登录绑定店铺创建、connectToken、Runtime session 绑定和重新登录。控制面接口。
任务与审批任务创建、状态和时间线查询、风险审批。控制面接口。
Runtime 回调运行步骤、审批请求、登录失效等事件回传。Agent / Runtime 回调接口。
运营数据同步创建同步任务、分批回传、完成确认和同步状态查询。只读采集控制面与数据写入接口。
运营数据查询店铺日报、趋势、商品、流量、广告、内容、库存和财务统计。SaaS 已采集数据的只读查询接口。

2. API 设计原则

  • 所有业务 API 必须在服务端解析用户身份、租户和店铺权限上下文。
  • 前端不得直接调用 MuleRun 或电商平台 API，也不得暴露 Runtime / Agent Key。
  • Agent 回调必须使用签名、时间戳和幂等键校验。
  • 运营数据采集遵循只读原则：Agent 只浏览、导出或调用平台只读数据接口。
  • 平台原始值与 AllMall 标准化值应可追溯；不得用 0 代替平台未提供的数据。
  • 接口返回明确的业务状态、数据区间、时区、数据新鲜度和质量信息。
  • 涉及高风险执行动作的任务必须走审批；运营数据采集任务不得包含执行动作。

4. 通用约定

4.1 Header

Authorization: Bearer <access_token>
X-AllMall-Request-Id: req_20260717_001
X-AllMall-Idempotency-Key: idem_sync_20260717_001
X-AllMall-Timestamp: 2026-07-17T09:30:00+08:00
X-AllMall-Signature: hmac-sha256=<signature>

X-AllMall-Idempotency-Key、时间戳和签名对 Agent 写入回调必填；Portal 的 GET 请求无需幂等键。

4.2 响应信封

{
  "success": true,
  "requestId": "req_20260717_001",
  "data": {},
  "error": null
}
{
  "success": false,
  "requestId": "req_20260717_001",
  "data": null,
  "error": {
    "code": "OPERATIONS_DATA_NOT_READY",
    "message": "Requested date has not completed synchronization",
    "retryable": true
  }
}

4.3 时间与统计区间

  • 时间戳使用 RFC 3339；业务日期使用 YYYY-MM-DD。
  • 默认使用店铺配置时区；未配置时使用 Asia/Shanghai。
  • dateFrom 与 dateTo 均为闭区间业务日期。
  • 日报以平台后台展示的自然日为准；接口必须返回 timezone 和 dataThrough。

4.4 金额、比例与缺失值

  • 金额使用整数最小货币单位，例如人民币分：{ "amount": 128800, "currency": "CNY" }。
  • 比例统一使用 0 到 1 的小数，例如 3.25% 表示为 0.0325。
  • ROI 使用倍数，例如投入 100 元带来 300 元成交额，roi = 3.0。
  • 平台不提供、权限不足或口径无法映射时返回 null，并在 quality.issues 中说明原因。

4.5 分页与排序

GET /api/operations/products?storeId=store_001&date=2026-07-16&limit=50&cursor=cur_xxx&sort=-gmv

默认 limit=50，最大 limit=200。响应返回 nextCursor；排序字段前的 - 表示降序。

5. 创建店铺

POST/api/stores

方向：Portal → SaaS。创建租户下的店铺资源，初始状态为待授权。

Request Body

{
  "platform": "tiktok_shop",
  "storeName": "Demo TikTok Store",
  "platformRegion": "CN",
  "timezone": "Asia/Shanghai"
}

Response · 201 Created

{
  "success": true,
  "requestId": "req_20260717_101",
  "data": {
    "storeId": "store_001",
    "platform": "tiktok_shop",
    "storeName": "Demo TikTok Store",
    "platformRegion": "CN",
    "timezone": "Asia/Shanghai",
    "authorizationStatus": "pending",
    "createdAt": "2026-07-17T10:00:00+08:00"
  },
  "error": null
}

约束

  • platform 支持 taobao、pinduoduo、tiktok_shop 和 jd。
  • 店铺创建不代表平台授权完成；成功绑定 Runtime session 后才可变更为 connected。
  • 租户内相同平台店铺的唯一性应在取得平台店铺标识后校验。

6.3 生成重新登录令牌

POST/api/stores/{storeId}/reauth-token

方向：Portal → SaaS。平台 session 失效或需要人工验证时，生成重新登录令牌。

Request Body

{
  "reason": "session_expired",
  "runtimeProvider": "mulerun"
}

Response · 201 Created

{
  "success": true,
  "requestId": "req_20260717_104",
  "data": {
    "reauthToken": "arkops_reauth_xxx",
    "storeId": "store_001",
    "reason": "session_expired",
    "expiresAt": "2026-07-17T10:30:00+08:00",

约束

  • SaaS 只保存加密的 session 引用，不保存电商平台账号密码。
  • Runtime 回调必须校验签名、时间戳、令牌用途、店铺归属和幂等键。

10. 日常运营数据模型

Agent 从平台后台读取数据后，按以下 datasetType 标准化。单次同步可只请求部分数据集；平台不支持的数据集应标记为 unsupported，不可伪造空记录。

datasetType粒度核心字段日常用途
store_daily_summary店铺 × 日访客、浏览量、点击、支付订单、销量、GMV、转化率、UV 价值、退款率、差评数。每日经营总览。
product_daily_performance商品/SKU × 日曝光、访客、点击率、转化率、销量、GMV、退款率。爆款、利润款及异常商品对比。
keyword_daily_ranking商品 × 关键词 × 日关键词、排名、搜索曝光、点击、成交。核心词与长尾词变化。
traffic_source_daily来源 × 日来源类型、访客、点击、订单、GMV、流量占比。免费、付费、私域流量结构。
ad_campaign_daily广告计划 × 日曝光、点击、花费、CPC、订单、成交额、转化率、ROI。只读分析投放效率。
inventory_snapshotSKU × 快照时刻在库、可售、锁定、在途、近 3/7/30 日销量。盘点、缺货与滞销风险统计。
content_daily_performance内容 × 日曝光、播放、完播率、互动、商品点击、订单、GMV。短视频和种草内容复盘。
live_session_performance直播场次观看人数、峰值在线、互动、商品点击、订单、GMV、转化率。直播周复盘。
activity_daily_performance活动 × 日访客、订单、销量、GMV、优惠金额、平台费用。活动效果统计。
finance_daily_summary店铺 × 日销售额、退款、广告费、平台费、物流费、商品成本、估算利润。周/月盈利核对。
数据口径：finance_daily_summary 中平台后台无法直接提供的成本或利润必须标记 isEstimated=true 并返回 calculationVersion。退款率和 GMV 应同时保留平台原始口径名称。

11. 创建运营数据同步

POST/api/operations/data-syncs

创建只读数据同步任务。推荐每天在店铺时区次日 02:00 后同步前一自然日，并允许最近 7 天回补。

Request Body

{
  "storeId": "store_001",
  "dateFrom": "2026-07-16",
  "dateTo": "2026-07-16",
  "datasetTypes": [
    "store_daily_summary",
    "product_daily_performance",
    "keyword_daily_ranking",
    "traffic_source_daily",
    "ad_campaign_daily",
    "inventory_snapshot",
    "content_daily_performance",
    "live_session_performance",
    "activity_daily_performance",
    "finance_daily_summary"
  ],
  "mode": "incremental",
  "reason": "scheduled_daily_sync"
}

Response · 202 Accepted

{
  "success": true,
  "requestId": "req_20260717_001",
  "data": {

20. 安全、审计与保留策略

  • Agent 使用店铺绑定产生的 Runtime session；账号密码、Cookie 和 session 原文不得进入运营数据 payload。
  • Agent 回调使用 HMAC-SHA256 签名；服务端校验 5 分钟时间窗、防重放和幂等键。
  • 每次同步记录租户、店铺、平台、任务、Runtime session 引用、数据集、记录数、操作者/触发器和时间线。
  • 原始页面导出或截图作为 artifact 单独加密存储，payload 只保存引用；访问遵循租户隔离和最小权限。
  • 默认保存标准化日报 24 个月、同步运行日志 12 个月；原始 artifact 保存期限由租户策略配置。
  • 包含买家个人信息的订单明细不属于本版采集范围；如平台导出文件包含个人信息，Agent 必须在回传前删除或脱敏。

21. 联调验收条件

  1. 可对一个已绑定店铺创建昨日数据同步，并查询到最终状态。
  2. Agent 可对至少三种数据集分批回传；重复批次不会产生重复数据。
  3. 同一业务日期重新同步后，默认查询返回最新完成版本，旧版本仍可审计追溯。
  4. 日报、趋势和商品维度的金额、比例、时区与平台后台抽样值一致。
  5. 平台无数据、无权限、登录失效和限流均返回明确状态，不以零值掩盖。
  6. 数据采集流程不会对平台侧订单、商品、广告、库存、内容、活动或用户产生任何写操作。
