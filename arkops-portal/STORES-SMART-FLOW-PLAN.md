# 店铺流程智能化 — 评估与优化计划

配套 `product-design.md`(拟新增决策 D7 + 店铺章节增补)。评估对象:店铺列表、店铺详情、连接/新建店铺流程,以及右上角「高级接入」入口。

**总体思路**:沿用商品同步确立的方法论 —— **系统主动检测 → 预算好推荐 → 结果先行 → 一键确认 → 少数升级到行动收件箱**。把当前"用户一步步操作、系统只做记录"的被动流程,变成"系统先查好、给建议,用户只拍板"的智能流程。

---

## 一、「高级接入」入口优化(点名项)

**现状**:右上角两个按钮并排——「高级接入」(文字按钮 → `/stores/new` 的 API Key / 账密表单)+「连接店铺」(主按钮 → 智能向导)。

**问题**:
- 命名含糊,且作为顶级动作与主 CTA 抢戏;对约 95% 商家是"陷阱"(没有 API Key、也不需要)。
- 本质是反智能的手动多步表单(平台 → 授权方式 → 授权配置 → 服务,全靠用户自选)。
- 与向导重复,只是技术路径。

**优化建议**:
1. 从顶部动作行**移除**,顶部只保留单一主 CTA「连接店铺」。
2. 把 API 路径**折叠进向导**,作为"安全连接"步骤里的上下文兜底:默认走扫码 / OAuth,下方一行小字"无法扫码?用 API Key 对接(开发者)",仅在需要时出现。
3. **改名**为具体的「API 对接 / 开发者接入」。
4. **系统自动推荐每个平台的最佳授权方式**(优先扫码 / OAuth),取消让用户在账密 / API Key / OAuth 间三选一的选择器——该选择器本身不智能。

## 二、店铺流程的智能化机会

### 1. 会话健康:从"被动等掉线"到"主动预警 + 批量续期"(最高价值)
- **现状**:掉线后状态变红、用户再点"重新登录",纯被动。
- **智能版**:
  - 主动预测到期:"拼多多授权将在 2 天后过期,建议现在续期"。
  - 批量续期:多家需要时"一键逐个续期",不必逐家点。
  - 这些"needs me"与商品同步一致,**升级进行动收件箱**,带推荐、一键处理。

### 2. 店铺列表:结果先行,而非一张要自己扫的表
- 顶部增加**健康摘要条**(对标商品的同步摘要卡):"3 家店 · 2 在线 · 1 家需重新登录 → 处理 · 上次检查 xx"。
- 把需要关注的店主动顶上来,而不是让用户逐行看状态列。

### 3. 连接后的"智能落地时刻"
- **现状**:连完店直接进空控制台。
- **智能版**:连接后立即检测并给结论 + 推荐动作——"已连接淘宝店,识别到 1236 商品 / 28410 订单;检测到未授权客服,Agent 无法自动回复 → 去补授权;推荐先开启差评巡检(只读)"。
- 引导流程结尾的 A9"第一个 Agent"已是雏形,扩展成"数据 + 服务缺口 + 推荐动作"的落地摘要。

### 4. 服务缺口的主动建议
- 店铺有服务标签(千川 / 飞鸽)。系统应**主动检测缺失的高价值服务**并建议开通(多个 Agent 依赖它们)——"这家店没连客服,客服 / 售后 Agent 用不了,去授权?"。
- 落点:店铺详情 + 行动收件箱。

### 5. 连新店时顺势铺货(跨功能联动)
- 连接新店后,若商家已有商品,主动提示"把 N 个已有商品铺货到这家新店"(复用商品迁移流),把"连接"与"铺货"两个原本割裂的动作串起来。

---

## 三、收敛

与商品一致,真正要用户看到的不是一堆控件,而是:
- 店铺列表顶部一条**健康摘要**(在线 / 需续期 / 服务缺口);
- 连接向导:**单一主 CTA + 系统推荐授权方式**,API 路径降级为上下文兜底;
- 需要决定的(续期、补服务、铺货建议)统一进**行动收件箱**,带推荐、一键。

---

## 四、建议范围与推进方式

**第一轮(投入产出最高、与现有模式最一致)**:
1. 「高级接入」降级折叠(移出顶部 → 向导内上下文兜底 + 改名 + 系统推荐授权方式)。
2. 店铺列表健康摘要条。
3. 会话到期主动预警 → 进行动收件箱(带批量续期)。

**下一轮**:
4. 连接后的智能落地摘要(数据 + 服务缺口 + 推荐动作)。
5. 服务缺口主动检测与建议。
6. 连新店顺势铺货。

**推进方式**:确认范围后,先更新 `product-design.md`(新增决策 D7 + 店铺章节增补),再出英文执行步骤(每节点完成后单独 commit),然后实现;每一步 `tsc` / `check-hex` / `build` 校验 + Chrome 视觉复查。
