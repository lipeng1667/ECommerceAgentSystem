# AutoAllMall 产品设计

> **一句话定义**：AutoAllMall 是一个 Agent 协同运营平台。不是"给你工具运营店铺"，而是"Agent 在运营店铺，你只需要处理例外"。
>
> 版本：design-v1 | 日期：2026-08-10 | 性质：全新产品骨架重构

---

## 一、产品哲学：三个根本切换

### 从"功能集合"到"Agent 协同"

| 旧的 AllMall | 新的 AutoAllMall |
|:--|:--|
| 侧边栏 = 10 个业务功能入口 | 侧边栏 = Agent 运营状态的 4 个视角 |
| 用户是操作员，逐一操作页面 | 用户是监督者，只看例外和决策 |
| Agent 是页面上的附加按钮 | Agent 是产品骨架本身 |
| 登录 → 看数据 → 去各个页面干活 | 登录 → 看 Agent 日报 → 处理例外 → 离开 |

### 从"人找事"到"事找人"

- **旧模式**：用户主动导航到"客服消息"，查看未回复会话
- **新模式**：客服 Agent 已经处理了 95% 的会话，把 3 条需要人工介入的推给你

### 从"管理工具"到"运营伙伴"

- **旧叙事**：这是你的多店铺管理系统
- **新叙事**：你的店铺有 N 个 Agent 在协同运营，这是它们的实时工作状态

## 二、信息架构

```
AutoAllMall
│
├── 🏠 运营中枢（首页）
│   ├── Agent 实时脉冲 — 哪些 Agent 在运行、运行状态
│   ├── 今日自动化成果 — 自动处理量、节省时间
│   ├── 决策队列 — 需要我处理的事情（3-5 条）
│   └── 店铺健康 — 不是 GMV，是自动化率、Agent 覆盖率
│
├── ⚡ 决策中心
│   ├── 待审批队列 — Agent 建议 + 等待确认
│   ├── 异常升级 — Agent 无法自动处理的事项
│   └── 历史决策 — 你的决策记录和 Agent 学习成果
│
├── 🤖 Agent 指挥部
│   ├── Agent 拓扑图 — 15 个 Agent 的协同关系可视化
│   ├── 自主等级 — 每个 Agent 的全自动/半自动/人工档位
│   ├── Agent 日志 — 每个 Agent 做了什么、为什么
│   └── Agent 市场 — 启用/配置新 Agent
│
└── 📊 业务透视
    ├── 商品线 — 商品 Agent 的运营成果
    ├── 订单线 — 订单 Agent 的处理记录
    ├── 客服线 — 客服 Agent 的会话摘要
    ├── 营销线 — 促销 Agent + 广告 Agent 的效果
    ├── 库存线 — 库存 Agent 的补货/调拨日志
    ├── 评价线 — 评价 Agent 的自动回复记录
    └── 直播线 — 直播 Agent 的场次成果
```

## 四、侧边栏重设计

```
AutoAllMall                    店铺：全部店铺 ▼

🏠 运营中枢                     ← 默认首页，Agent 日报

⚡ 决策中心              (3)    ← 待决策数 Badge

🤖 Agent 指挥部
   ├── Agent 协同图
   ├── 自主等级设置
   └── Agent 工作日志

📊 业务透视
   ├── 商品线                   ← Agent 视角的商品数据
   ├── 订单线
   ├── 客服线
   ├── 营销线（促销 + 广告）
   ├── 库存线
   ├── 评价线
   └── 直播线
─────────────────────
⚙️  设置
   ├── 店铺连接
   ├── 成员管理
   ├── 计费
   └── 帮助
```

- 4 个一级入口，不是 13 个
- 业务透视是二级，不是平铺
- 设置缩到最后，不是主角
- 决策中心有实时数字提醒

## 五、与旧版 AllMall 的核心差异总结

| 维度 | AllMall（旧） | AutoAllMall（新） |
|:--|:--|:--|
| **产品骨架** | 业务功能菜单 | Agent 协同视图 |
| **第一屏** | GMV + 订单数 + 图表 | Agent 运行状态 + 决策队列 |
| **用户角色** | 操作员（去各个页面干活） | 监督者（审批 Agent 的建议） |
| **交互模式** | 人导航 → 人操作 | Agent 推送 → 人决策 |
| **信息层级** | 13 个一级功能入口 | 4 个一级入口 |
| **Agent 位置** | 最后一级（设置区） | 第一级（首页核心） |
| **自动化感知** | 几乎不存在 | 自动化率是最核心的 KPI |
| **数据展示** | 静态统计卡片 | 标注"自动/人工"的动态列表 |
| **叙事逻辑** | 我们提供工具帮你管店 | Agent 在帮你运营，你只需决策 |

## 六、实施建议

**复用而非重写**：下方"业务透视"中的所有 Agent 工作日志和数据表格，底层可以复用现有 AllMall 的 API 和页面组件。改变的是信息的**组织方式**和**叙事框架**，不是数据源。

**渐进式迁移**：
1. Phase 1 — 新建 AutoAllMall 入口，完成运营中枢 + 决策中心
2. Phase 2 — 将业务透视接入现有 API，Agent 化展示
3. Phase 3 — Agent 指挥部可视化，自主等级体系
4. Phase 4 — 从 AllMall 完全迁移，下线旧版
